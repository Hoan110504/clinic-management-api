🤖 1. AI CHATBOT - Trợ Lý Y Tế Thông Minh

POST /api/ai/chat

AI Chatbot là trợ lý y tế thông minh sử dụng Google Gemini 2.0 Flash, giúp người dùng tra cứu thông tin về thuốc, dịch vụ, lịch hẹn và hồ sơ bệnh án một cách nhanh chóng và chính xác.

📋 Luồng Hoạt Động Chi Tiết

1 Client Gửi Request
File Frontend: (Không có trong backend code)
Client gửi POST request đến /api/ai/chat với body: { "message": "Thuốc trị sốt giá bao nhiêu?" }
2 Routing - Định Tuyến Request
File: src/routes/ai.routes.js
Router nhận request và chuyển qua chuỗi middleware trước khi đến controller.
3 Middleware Chain - Xác Thực & Bảo Mật
3.1 Authentication: src/middleware/auth.js - Kiểm tra JWT token, xác thực người dùng
3.2 Rate Limiter: src/middleware/aiRateLimiter.js - Giới hạn 20 request/user/10 phút, 50 request/IP/10 phút
3.3 Input Sanitizer: src/middleware/aiSanitizer.js - Xóa HTML tags, phát hiện prompt injection, giới hạn 500 ký tự
4 Controller - Xử Lý Logic
File: src/controllers/ai.controller.js (function: chat)
Controller orchestrates toàn bộ luồng two-pass AI và timeout 30 giây.
5 Conversation Manager - Quản Lý Lịch Sử
File: src/services/conversationManager.js
Lấy 10 tin nhắn gần nhất từ session, thêm tin nhắn mới của user vào lịch sử.
6 PASS 1 - AI Chọn Queries
File: src/services/gemini.service.js (function: selectQueries)
AI phân tích câu hỏi của user và chọn các query_ids phù hợp từ whitelist:
Whitelist: src/config/queryWhitelist.js
Ví dụ: User hỏi về giá thuốc → AI chọn query "medicines_and_services"
AI trả về: ["medicines_and_services"]
7 Query Handler - Thực Thi Queries
File: src/services/queryHandler.service.js
Thực thi các queries được AI chọn với role-based filtering:
- Kiểm tra quyền truy cập theo role (Admin, Doctor, Patient...)
- Thực thi query handler tương ứng từ queryWhitelist.js
- Truy vấn database qua Sequelize ORM
Models sử dụng: src/models/Medicine.js, src/models/LabService.js, v.v.
8 PASS 2 - AI Tổng Hợp Câu Trả Lời
File: src/services/gemini.service.js (function: synthesizeAnswer)
AI nhận kết quả queries + lịch sử hội thoại, tạo câu trả lời tự nhiên bằng tiếng Việt:
Input: Query results + Conversation history
Output: "Phòng khám có Paracetamol 500mg giá 2.000đ/viên, Ibuprofen 400mg giá 3.500đ/viên..."
9 Conversation Manager - Lưu Response
File: src/services/conversationManager.js
Lưu câu trả lời của AI vào lịch sử hội thoại trong session memory (giới hạn 10 tin nhắn).
10 Chat Logger - Ghi Log Audit
File: src/services/chatLogger.service.js
Ghi lại toàn bộ tương tác vào database:
Model: src/models/AiChatLog.js
Lưu: user_id, user_role, user_message, ai_response, selected_query_ids, timestamp, ip_address, response_time_ms
11 Response Trả Về Client
Controller trả về JSON response:
{ "success": true, "data": { "response": "...", "queryIds": [...], "remainingRequests": 15 } }

🔒 Tính Năng Bảo Mật

  • JWT Authentication: Yêu cầu đăng nhập cho mọi request
  • Rate Limiting: 20 request/user/10 phút, 50 request/IP/10 phút
  • Input Sanitization: Xóa HTML tags, script injection patterns
  • Prompt Injection Detection: 40+ patterns phát hiện jailbreak attempts
  • Role-Based Access Control: Queries được filter theo quyền user
  • Audit Logging: Ghi lại mọi tương tác vào database
  • Timeout Protection: Request timeout sau 30 giây
  • Hardcoded System Prompt: AI behavior không bị user thay đổi
💡 Two-Pass AI Flow: Kiến trúc độc đáo giúp AI chọn đúng dữ liệu cần thiết (Pass 1) trước khi tổng hợp câu trả lời (Pass 2), đảm bảo câu trả lời chính xác và có căn cứ từ database.

💊 2. AI PHÂN TÍCH PHẢN ỨNG THUỐC

POST /api/ai/check-prescription

Hệ thống AI phân tích tương tác thuốc, phát hiện chống chỉ định và đưa ra cảnh báo an toàn cho bác sĩ trước khi kê đơn.

📋 Luồng Hoạt Động Chi Tiết

1 Bác Sĩ Gửi Request Kiểm Tra
Client gửi POST request với thông tin:
{ "patientId": 123, "medicines": [{medicineName, dosage, instructions}], "currentDiagnosis": "..." }
2 Routing & Authentication
File: src/routes/ai.routes.js - Route: router.post('/check-prescription', authorize(ROLES.DOCTOR), ...)
Chỉ bác sĩ (role = 2) mới có quyền truy cập endpoint này.
3 Controller - Validate Input
File: src/controllers/ai.controller.js (function: checkPrescriptionSafety, lines 610-667)
- Kiểm tra role = 2 (Doctor)
- Validate danh sách thuốc không rỗng
- Validate patientId hợp lệ
4 Lấy Thông Tin Bệnh Nhân
Model: src/models/Patient.js
Query database lấy:
- Tiền sử bệnh (medicalHistory)
- Dị ứng (allergies)
- Tuổi (tính từ dateOfBirth)
- Giới tính (gender)
5 Lấy Thuốc Đang Dùng (30 Ngày Gần Nhất)
Models: src/models/Prescription.js, src/models/PrescriptionItem.js, src/models/Medicine.js
Query các đơn thuốc có status = 0 hoặc 1 (đang chờ/đã cấp) trong 30 ngày gần nhất của bệnh nhân này.
6 Patient Safety Service - Phân Tích
File: src/services/patientSafetyService.js (function: checkPrescriptionSafety)
Service tạo prompt chi tiết gửi đến Gemini AI với:
- Thông tin bệnh nhân (tiền sử, dị ứng, tuổi, giới tính, chẩn đoán)
- Danh sách thuốc đang dùng
- Danh sách thuốc mới kê
7 Gemini AI - Phân Tích An Toàn
File: src/services/gemini.service.js
AI phân tích 4 khía cạnh:
1. Tương tác trong đơn thuốc mới
2. Tương tác với thuốc đang dùng
3. Chống chỉ định (Tiền sử & Dị ứng)
4. Phù hợp chẩn đoán
Retry: 3 lần với exponential backoff (2s, 4s, 8s)
8 Parse JSON Response
File: src/services/patientSafetyService.js
Parse response AI thành JSON format:
{ "safe": true/false, "warnings": [{level, issue, recommendation}], "message": "..." }
Nếu parse lỗi → Fallback response: safe=false với thông báo lỗi.
9 Response Trả Về Bác Sĩ
Controller trả về kết quả phân tích cho bác sĩ:
{ "success": true, "data": { "safe": false, "warnings": [...], "message": "..." } }

  • Routes: src/routes/ai.routes.js
  • Controller: src/controllers/ai.controller.js (checkPrescriptionSafety, lines 610-667)
  • Services: src/services/patientSafetyService.js
  • Services: src/services/gemini.service.js
  • Middleware: src/middleware/auth.js
  • Models: src/models/Patient.js
  • Models: src/models/Prescription.js
  • Models: src/models/PrescriptionItem.js
  • Models: src/models/Medicine.js
  • Models: src/models/MedicalExamination.js

🔒 Tính Năng Bảo Mật

  • Doctor-Only Access: Chỉ bác sĩ (role=2) có quyền sử dụng
  • Patient Data Protection: Chỉ truy cập dữ liệu bệnh nhân được chỉ định
  • No External API Calls: Không gửi dữ liệu ra ngoài ngoại trừ Gemini AI
  • Retry Mechanism: Xử lý lỗi API với exponential backoff
  • Fallback Response: Không để hệ thống crash khi AI lỗi
💡 AI Clinical Pharmacist: Hệ thống đóng vai trò dược sĩ lâm sàng AI, kiểm tra đơn thuốc 24/7, phát hiện ngay các vấn đề về tương tác thuốc và chống chỉ định trước khi bác sĩ kê đơn.

📋 3. AI TÓM TẮT HỒ SƠ BỆNH ÁN

POST /api/ai/summarize-medical-record

AI tự động tóm tắt toàn bộ hồ sơ bệnh án thành 3-5 dòng ngắn gọn, giúp bác sĩ nắm bắt nhanh tiền sử bệnh, tình trạng hiện tại và các điểm cần lưu ý trước khi khám.

📋 Luồng Hoạt Động Chi Tiết

1 Bác Sĩ Yêu Cầu Tóm Tắt
Client gửi POST request:
{ "medicalRecordId": 123, "patientId": 456 }
2 Routing & Middleware
File: src/routes/ai.routes.js
Middleware chain:
- Authentication (JWT)
- AI Summary Rate Limiter: src/middleware/aiSummaryRateLimiter.js
  → 10 lần/giờ/bệnh nhân, 30 lần/phút/toàn bộ
- Request Validator
3 Controller - Orchestrate Flow
File: src/controllers/ai.controller.js (function: summarizeMedicalRecord, lines 533-609)
Chuyển request đến Medical Summary Service.
4 Medical Summary Service - Check Cache
File: src/services/medicalSummary.service.js
Kiểm tra xem bệnh án này đã có summary trong vòng 1 giờ chưa:
Model: src/models/MedicalExamination.js (fields: AiSummary, AiSummaryGeneratedAt)
Nếu có cache → Trả về ngay, không gọi AI.
5 Execute 8 Pre-Defined Queries
File: src/config/medicalSummaryQueries.js
Thực thi song song 8 queries chỉ đọc (read-only):
1. getPatientBasicInfo - Thông tin cơ bản
2. getMedicalHistory - 10 lần khám gần nhất
3. getChronicDiseases - Bệnh mãn tính
4. getAllergies - Dị ứng
5. getRecentLabTests - Xét nghiệm 6 tháng
6. getCurrentMedications - Thuốc đang dùng
7. getPreviousDiagnoses - Chẩn đoán cũ
8. getVitalSignsHistory - Sinh hiệu 5 lần gần nhất
6 Format Data cho AI
File: src/services/medicalSummary.service.js
Chuyển đổi query results thành văn bản có cấu trúc dễ đọc cho AI.
7 Gemini AI - Tóm Tắt
File: src/services/gemini.service.js
System Prompt: Đóng vai bác sĩ nội khoa giàu kinh nghiệm
Yêu cầu: Tóm tắt 3-5 dòng theo cấu trúc:
- Tiền sử bệnh (Medical History)
- Bệnh lý hiện tại (Current Conditions)
- Điểm cần lưu ý (Important Notes)
Retry: 3 lần với delays [2s, 4s, 8s]
Timeout: 30 giây
8 Lưu Summary vào Database
Model: src/models/MedicalExamination.js
Update fields:
- AiSummary: Nội dung tóm tắt
- AiSummaryGeneratedAt: Timestamp
Cache này có hiệu lực 1 giờ.
9 Response Trả Về
Controller trả về:
{ "success": true, "data": { "summary": "...", "queryIds": [...], "generatedAt": "...", "remainingRequests": 8, "cached": false } }

🔒 Tính Năng Bảo Mật

  • Doctor-Only Access: Chỉ bác sĩ (role=2) có quyền sử dụng
  • Two-Level Rate Limiting: Per-patient (10/giờ) + Global (30/phút)
  • Read-Only Queries: 8 queries pre-defined, không cho phép custom query
  • Cache Layer: Giảm tải API, cache 1 giờ
  • Timeout Protection: 30 giây timeout
  • Retry Mechanism: 3 attempts với exponential backoff
💡 Pre-Defined Queries Architecture: Thay vì cho AI tự viết SQL query (nguy hiểm), hệ thống sử dụng 8 queries được định nghĩa sẵn, AI chỉ đọc và tóm tắt dữ liệu, đảm bảo an toàn 100%.

📱 4. QUÊN MẬT KHẨU BẰNG TELEGRAM

POST /api/auth/forgot-password (channel: telegram)

Hệ thống cho phép người dùng đặt lại mật khẩu qua Telegram bot, nhận OTP 6 số trực tiếp trong cuộc trò chuyện Telegram.

📋 Luồng Hoạt Động Chi Tiết

🔗 Giai Đoạn 1: Liên Kết Telegram (One-Time Setup)

1 User Nhấn "Liên Kết Telegram"
Frontend tạo deep link: https://t.me/YourBot?start=PHONE_0866816201
2 User Bấm /start Trên Telegram
Telegram bot nhận webhook hoặc polling message với text: /start PHONE_0866816201
3 Telegram Service - Xử Lý /start
File: src/services/telegram.service.js (function: handleStartCommand)
Parse phone từ start parameter, lấy chat_id của user.
4 Lưu Link Session
Model: src/models/TelegramLinkSession.js
Lưu mapping: phone → telegramChatId
Bot gửi tin nhắn xác nhận liên kết thành công.
5 Frontend Polling Status
File: src/routes/auth.routes.js (GET /api/auth/telegram-link-status?phone=xxx)
Controller: src/controllers/auth.controller.js (telegramLinkStatus)
Frontend gọi API này để kiểm tra xem user đã bấm /start chưa.
6 Hoàn Tất Đăng Ký
Khi đăng ký tài khoản, backend lấy telegramChatId từ TelegramLinkSession và lưu vào User.telegramChatId.
Từ giờ user có thể nhận OTP qua Telegram.

🔑 Giai Đoạn 2: Quên Mật Khẩu - Nhận OTP

1 User Nhập Số Điện Thoại
Frontend gửi POST request: { "phone": "0866816201" }
2 Routing & Rate Limiter
File: src/routes/auth.routes.js (POST /api/auth/forgot-password)
Rate limit: 5 requests/giờ/user.
3 Controller - Tìm User
File: src/controllers/auth.controller.js (function: requestPasswordResetOtp, lines 531-607)
- Normalize phone (0866816201 → +84866816201)
- Tìm user trong database bằng phone hoặc email
- Check rate limit (5 lần/giờ)
- Check cooldown (60 giây giữa các lần gửi)
4 Generate OTP
File: src/services/passwordReset.service.js (function: generateOtpCode)
Tạo OTP 6 số random: 123456
5 Hash & Save OTP
File: src/services/passwordReset.service.js (function: hashResetValue)
Hash OTP với SHA256 + pepper, lưu vào database:
Model: src/models/PasswordResetOtp.js
Fields: userId, identifier, channel='telegram', destination=chatId, otpHash, expiresAt (10 phút)
6 Gửi OTP Qua Telegram
File: src/services/passwordReset.service.js (function: sendTelegramOtp)
Gửi POST request đến Telegram Bot API:
https://api.telegram.org/bot{token}/sendMessage
Tin nhắn: "Mã OTP đặt lại mật khẩu của bạn là: 123456"
7 Response Trả Về
Controller trả về:
{ "success": true, "data": { "message": "OTP đã được gửi", "channel": "telegram", "destinationMasked": "Telegram ...8201", "expiresInSeconds": 600 } }

✅ Giai Đoạn 3: Xác Thực OTP & Đặt Lại Mật Khẩu

1 User Nhập OTP
Frontend gửi: { "phone": "0866816201", "otp": "123456" }
Route: POST /api/auth/forgot-password/verify-otp
2 Controller - Verify OTP
File: src/controllers/auth.controller.js (function: verifyPasswordResetOtp, lines 659-709)
- Hash OTP user nhập
- So sánh với otpHash trong database (timing-safe comparison)
- Kiểm tra hết hạn (10 phút)
- Check attemptCount (max 5 lần thử sai)
- Nếu đúng: tạo resetToken, lưu verifiedAt
3 User Nhập Mật Khẩu Mới
Frontend gửi: { "phone": "0866816201", "resetToken": "xxx", "newPassword": "NewPass123!" }
Route: POST /api/auth/forgot-password/reset-password
4 Controller - Reset Password
File: src/controllers/auth.controller.js (function: resetPasswordWithOtp, lines 711-767)
- Verify resetToken hash
- Check expiresAt (10 phút)
- Hash mật khẩu mới bằng bcrypt
- Update User.password
- Set consumedAt (đánh dấu đã sử dụng)
5 Response Success
Trả về: { "success": true, "data": { "message": "Đặt lại mật khẩu thành công" } }
User có thể đăng nhập ngay với mật khẩu mới.

📁 Danh Sách Files Liên Quan

  • Routes: src/routes/auth.routes.js
  • Controller: src/controllers/auth.controller.js (requestPasswordResetOtp, verifyPasswordResetOtp, resetPasswordWithOtp)
  • Services: src/services/passwordReset.service.js
  • Services: src/services/telegram.service.js
  • Models: src/models/PasswordResetOtp.js
  • Models: src/models/TelegramLinkSession.js

🔒 Tính Năng Bảo Mật

  • OTP Hashing: SHA256 + pepper, không lưu plaintext OTP
  • Rate Limiting: 5 lần gửi OTP/giờ
  • Resend Cooldown: 60 giây giữa các lần gửi
  • OTP Expiration: 10 phút
  • Max Attempts: 5 lần thử sai OTP
  • One-Time Use: consumedAt đánh dấu OTP đã dùng
  • Timing-Safe Comparison: Chống timing attack khi so sánh hash
  • Session Linking: Telegram chat_id phải được liên kết trước

📧 5. QUÊN MẬT KHẨU BẰNG EMAIL

POST /api/auth/forgot-password (channel: email)

Hệ thống hỗ trợ đặt lại mật khẩu qua email SMTP, gửi OTP 6 số đến địa chỉ email đã đăng ký của người dùng.

📋 Luồng Hoạt Động Chi Tiết

1 User Nhập Email
Frontend gửi POST request: { "email": "user@example.com" }
2 Routing & Rate Limiter
File: src/routes/auth.routes.js (POST /api/auth/forgot-password)
Cùng endpoint với Telegram, rate limit: 5 requests/giờ.
3 Controller - Auto Detect Channel
File: src/controllers/auth.controller.js (requestPasswordResetOtp)
Service: src/services/passwordReset.service.js (resolveIdentifierChannel)
Tự động phát hiện:
- Email regex: /^[^\s@]+@[^\s@]+\.[^\s@]+$/ → channel='email'
- Phone regex: /^[0-9+\-\s()]{3,15}$/ → channel='telegram'
4 Tìm User & Generate OTP
Tương tự Telegram flow:
- Normalize email (lowercase)
- Tìm user trong database
- Generate OTP 6 số
- Hash với SHA256 + pepper
- Lưu vào PasswordResetOtp với channel='email'
5 SMTP Service - Gửi Email
File: src/services/passwordReset.service.js (sendEmailOtp)
Sử dụng nodemailer với config từ .env:
- SMTP_HOST (ví dụ: smtp.gmail.com)
- SMTP_PORT (587 hoặc 465)
- SMTP_USER
- SMTP_PASS
- SMTP_FROM

Email content (HTML + Text):
Subject: "Mã xác thực đặt lại mật khẩu"
Body: "Mã OTP của bạn là: 123456. Có hiệu lực 10 phút."
6 User Nhận Email & Nhập OTP
User kiểm tra email, copy OTP 6 số, nhập vào form.
7 Verify OTP & Reset Password
Flow giống y hệt Telegram:
- POST /api/auth/forgot-password/verify-otp
- POST /api/auth/forgot-password/reset-password
Controller, service, model đều dùng chung với Telegram flow.

📁 Danh Sách Files Liên Quan

  • Routes: src/routes/auth.routes.js
  • Controller: src/controllers/auth.controller.js (requestPasswordResetOtp, verifyPasswordResetOtp, resetPasswordWithOtp)
  • Services: src/services/passwordReset.service.js (sendEmailOtp, getSmtpTransport)
  • Models: src/models/PasswordResetOtp.js (channel='email')
  • Models: src/models/User.js
  • NPM Package: nodemailer

🔒 Tính Năng Bảo Mật

  • Unified Flow: Email và Telegram dùng chung code, chỉ khác channel
  • SMTP Security: TLS/SSL encryption cho kết nối SMTP
  • OTP Hashing: SHA256 + pepper như Telegram
  • Rate Limiting: 5 lần gửi OTP/giờ (chung với Telegram)
  • Email Masking: Response chỉ hiện "u***@example.com"
  • Fallback: Development mode log OTP nếu không config SMTP
💡 Multi-Channel Architecture: Hệ thống được thiết kế để hỗ trợ nhiều kênh gửi OTP (Telegram, Email, SMS trong tương lai) với cùng một codebase, chỉ khác nhau ở service gửi tin nhắn.

Authentication & Authorization

  • JWT-based authentication cho mọi protected endpoints
  • Role-based access control (Admin, Doctor, Receptionist, Pharmacist, Patient, LabTech)
  • Token expiration và refresh mechanism

Rate Limiting & Throttling

  • AI Chatbot: 20 requests/user/10min, 50 requests/IP/10min
  • AI Summary: 10 requests/patient/hour, 30 requests/doctor/minute
  • Password Reset: 5 requests/hour, 60s cooldown between sends
  • In-memory storage với automatic cleanup

Input Validation & Sanitization

  • HTML tag stripping (40+ patterns)
  • Script injection detection
  • Prompt injection detection (40+ patterns)
  • Max length enforcement (500 chars for chat)
  • Email và phone number validation

Data Protection

  • Password hashing với bcrypt (salt rounds: 10)
  • OTP hashing với SHA256 + pepper
  • Timing-safe comparison để chống timing attacks
  • Database query parameterization (SQL injection prevention)
  • Sensitive data masking trong responses

AI Security

  • Hardcoded system prompts (không thể bị user override)
  • Query whitelist architecture (chỉ cho phép pre-defined queries)
  • Role-based query filtering
  • AI response validation và sanitization
  • Timeout protection (30 seconds)

Audit & Logging

  • AiChatLog: Ghi lại mọi tương tác với AI chatbot
  • PasswordResetOtp: Audit trail cho password reset attempts
  • Winston logger: System-level logging

  • IP address tracking

⚠️ Error Handling & Retry Mechanisms

AI Service Error Handling
  • Gemini API 429 (Rate Limit): Retry 3 lần với delays [2s, 4s, 8s]
  • Gemini API 500 (Internal Error): Model fallback (Gemini 2.0 → 1.5 Pro → 1.5 Flash)
  • JSON Parse Error: Fallback response thay vì crash
  • Timeout: 30 giây cho mỗi AI request
  • Network Error: User-friendly error messages
Password Reset Error Handling
  • User Not Found: Generic response (không tiết lộ user tồn tại hay không)
  • OTP Expired: Clear error message với hướng dẫn request OTP mới
  • Max Attempts: Block OTP verification sau 5 lần thử sai
  • SMTP Error: Fallback to console log trong development mode
  • Telegram API Error: Retry logic với exponential backoff
Database Error Handling
  • Connection Error: Automatic reconnection với retry
  • Query Timeout: 30 giây timeout cho mỗi query
  • Constraint Violation: User-friendly error messages
  • Transaction Rollback: Đảm bảo data consistency

⚡ Performance Optimizations

Caching Strategies
  • AI Summary Cache: 1 giờ TTL trong database
  • Conversation History: In-memory cache (10 tin nhắn gần nhất)
  • Query Results: Session-based caching
Database Optimizations
  • Indexes: Phone, Email, TelegramChatId, UserId
  • Query Limiting: Giới hạn số lượng records (10-100 rows)
  • Selective Fields: Chỉ lấy fields cần thiết
  • Parallel Queries: Execute multiple queries đồng thời
AI Request Optimization
  • Two-Pass Flow: Giảm token usage, tăng accuracy
  • Context Limiting: Chỉ gửi 10 tin nhắn gần nhất
  • Temperature Control: 0.1 cho JSON, 0.7 cho chat
  • Request Queue: Tránh overwhelm Gemini API
Memory Management
  • Rate Limit Store Cleanup: Mỗi 5 phút
  • Session Cleanup: Expired entries tự động xóa
  • Streaming Responses: Không load toàn bộ vào memory
